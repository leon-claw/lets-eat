# 周围菜品小程序端设计

## 背景

Web 端已经实现“周围菜品”：获取当前位置或用户选择的位置，向高德搜索附近餐饮，按评分取候选商家，再用本地分类规则将商家归入内置大类，生成复用现有左右滑动游戏的菜品卡片。小程序端需要提供同样的端到端流程。

## 已确认的产品规则

1. 小程序端的高德 `key` 和 `securityJsCode` 由用户自行填写。
2. 两个配置只保存在当前小程序设备本地，开发者不提供、不写入后端环境变量，也不打包进代码。
3. 小程序直接调用高德 Web Service 周边搜索接口；用户需要在高德控制台为自己的 Key 配置小程序请求合法域名，并使用 Web 服务 API 类型的 Key。
4. 每次搜索最多获取 200 个候选商家，从候选中按评分降序取用户设置的 10、20 或 30 家展示和参与游戏。
5. 搜索结果保留高德原始分类、评分、坐标、地址、营业信息和图片 URL 等可用字段；游戏卡片封面使用内置菜品大类封面，不使用高德图片，避免游戏过程中加载缓慢。
6. 分类只使用内置“大类菜品”模板，不使用内置小类；无法可靠归类或没有对应大类模板的商家不进入游戏。
7. 同一大类只生成一张卡片，卡片下方展示聚合后的真实门店名称，并使用超长截断；游戏过程沿用现有小程序单人游戏的卡片、左右滑动、喜欢/不喜欢和撤销交互。
8. 游戏结果保存在设备本地，完成后可返回“确认菜品数据集”页面；搜索会话和未完成游戏可恢复。

## 小程序流程

`确认菜品数据集` → `周围菜品` → 定位/手动选择位置 → 调整搜索范围和数量 → 搜索 → 查看门店列表 → 开始游戏 → 现有滑动游戏 → 现有单人结果页。

当没有高德配置时，周围菜品入口进入设置页并带回跳标记。保存成功后回到周围菜品页并自动开始定位/搜索。定位失败时保留上次位置或允许用户手动选择位置，并显示可重试操作。

## 技术边界

- 使用 `wx.getLocation({ type: 'gcj02' })` 获取当前位置，使用 `wx.chooseLocation` 作为手动选点兜底，不在小程序中嵌入高德 Web JS 地图。
- 通过 `wx.request` 直接请求 `https://restapi.amap.com/v3/place/around`，分页获取最多 4 页、每页 50 条；解析 `pois`、评分和 `photos`。
- 纯 TypeScript 的商家分类规则放入 `client-core`，Web 与小程序共享；Web 端继续使用 fastText 作为主分类，小程序端使用同一套高精度规则适配器。
- 小程序使用单独的本地存储键保存高德配置、最近搜索和周围菜品游戏轮次，不改变现有菜单、多人轮次和自定义菜品存储格式。
- 高德请求失败时不伪造结果；若存在上一次有效搜索则保留结果并提供重新定位/搜索按钮。

## 安全和配置说明

高德 Key 属于用户自备配置，必须以用户输入为来源。代码、示例配置、后端环境变量和构建产物不得包含项目开发者的 Key。由于请求在小程序客户端发起，真实发布前还必须在微信小程序后台加入 `https://restapi.amap.com` 为 request 合法域名；合法域名不是代码可以替代的配置。
