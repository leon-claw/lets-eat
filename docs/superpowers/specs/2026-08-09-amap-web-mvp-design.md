# 高德附近餐饮 Web MVP 设计

## 目标

验证高德 Web JS API 在不同中国城市是否能够稳定返回附近餐饮 POI，并直接展示名称、位置、餐饮类型、距离和营业时间。

## 用户流程

1. 用户选择省份。
2. 城市选择器联动显示该省城市，用户选择城市。
3. 地图跳转到城市中心点，并自动搜索中心点 2 公里范围内的餐饮。
4. 页面以地图标记和左侧列表展示结果。
5. 用户拖动地图后点击“在此区域搜索”，以新的地图中心重新搜索。
6. 点击列表项或地图标记，查看该 POI 的名称、类型、地址、距离和营业时间。

## 范围

### 包含

- 省 / 市两级联动选择器。
- 城市中心点定位。
- 高德地图 Web JS API 2.0。
- `AMap.PlaceSearch.searchNearBy` 附近餐饮搜索。
- 固定 2 公里搜索范围。
- 地图、结果列表、POI 详情联动。
- 营业时间原样展示；高德没有返回时展示“未提供”。
- 高德 Key 错误、无结果、接口失败和缺少营业时间的明确提示。

### 不包含

- 餐饮类型筛选。
- “帮我选一家”推荐逻辑。
- 数据完整率统计和 JSON / CSV 导出。
- 用户账号、收藏、评价、商家入驻和后台管理。
- 后端、数据库和跨城市批量抓取。

## 技术方案

- 使用当前项目的静态 Web 页面，不引入后端和复杂框架。
- 省市数据作为本地静态配置，避免额外接口依赖。
- 高德 Key 和 `securityJsCode` 放在本地 `config.js`，不写入业务代码。
- 城市选择只负责改变地图中心；POI 数据只在用户主动搜索时请求。
- 结果字段统一归一化为：`id`、`name`、`type`、`address`、`distance`、`hours`、`location`。
- 供应商字段缺失时不猜测、不补造，直接显示“未提供”。

## 页面结构

- 顶部：产品名、当前数据状态。
- 左侧：省市选择器、搜索按钮、POI 结果列表。
- 右侧：高德地图、用户当前搜索中心、POI 标记、“在此区域搜索”按钮。
- 移动端：地图在上、结果列表在下。

## 验证标准

- 用户可以手动选择至少三个不同城市并完成搜索。
- 每个城市都能看到地图和 POI 列表，或看到明确的无结果 / 错误状态。
- POI 列表能展示名称、位置或地址、类型、距离和营业时间字段状态。
- 拖动地图后不会自动高频请求，只有点击“在此区域搜索”才发起新查询。
- 没有配置高德 Key 时仍可使用演示数据预览页面结构。
