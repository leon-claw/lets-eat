# 周围菜品 fastText WebAssembly 推理设计

日期：2026-09-12

状态：已确认方案，待实现

关联设计：`2026-09-12-nearby-food-smart-category-design.md`

## 1. 目标

将已经训练并评估过的 fastText 餐厅分类模型应用到 Web 版“周围菜品”页面，替换当前仅由 TypeScript 规则计算的主要分类路径，同时为后续微信小程序端复用同一模型和分类协议保留适配边界。

本阶段只实现 Web 端真实模型推理，不修改搜索排序、门店数量、游戏卡片、多人同步或小程序页面。

当前模型产物：

- `nearby-restaurant-classifier.ftz`：量化模型，作为运行时模型。
- `nearby-restaurant-classifier.bin`：非量化模型，仅保留用于训练和离线评估，不进入 Web 首屏资源。
- 模型训练参数、标签和数据格式以训练配置及训练脚本为准。

## 2. 用户可见行为

周围商家列表仍按现有顺序和数量展示。每家商家继续显示：

```text
商家名称                         评分
高德分类：餐饮服务 · 中餐厅
智能分类：粤菜
```

- 只对当前列表中展示的前 20 家商家进行智能分类。
- 高德原始分类继续展示，不被模型结果覆盖。
- 模型初始化期间暂时显示现有规则分类结果，避免列表空白或等待阻塞。
- 模型初始化成功后，用 fastText 结果替换规则分类结果。
- 模型加载失败、WASM 不可用、预测异常或结果无法映射时，继续使用规则分类；规则分类仍以“其他”为最终兜底。
- 不向普通用户展示模型加载状态、置信度、原始标签或 WASM 技术细节。

## 3. 模型输入与输出

必须严格复用训练时的输入格式，避免训练和线上特征不一致。

训练样本格式为：

```text
__label__粤菜 name_广州酒家 amap_餐饮服务 amap_中餐厅 amap_广东菜_粤菜
```

线上预测输入去掉标签部分，使用：

```text
name_商家名称 amap_高德分类层级1 amap_高德分类层级2 ...
```

格式化规则：

1. 清理换行、制表符、竖线和多余空格。
2. 商家名称中的空格转换为下划线。
3. 高德分类按空格和 `|` 拆分为多个层级特征。
4. 高德分类中的括号和斜线转换为下划线，保持与训练脚本一致。
5. 空名称或空分类也必须生成合法输入，由分类器或回退逻辑处理。

模型返回的 `__label__xxx` 去掉 fastText 标签前缀后，再映射到应用内置大类。只接受训练数据中的合法标签：

```text
粤菜、川菜、湘菜、火锅、烧烤、螺蛳粉、日料、韩餐、西餐、东南亚菜、
东北菜、云南菜、面食、轻食、甜品奶茶、海鲜、其他
```

## 4. Web 运行时

采用官方 fastText WebAssembly 运行时：

```text
fasttext.js
fasttext_wasm.js
fasttext_wasm.wasm
nearby-restaurant-classifier.ftz
```

资源作为 Web 静态资源提供，由页面按需懒加载。页面首次进入周围菜品列表时初始化一次运行时并加载模型；同一页面生命周期内复用已经加载的模型实例，避免每家商家重复初始化 WASM。

不引入 ONNX Runtime、Transformers.js 或其他大模型运行时依赖。当前任务是短文本、固定 17 类的小型分类，fastText WASM 已足够满足模型能力和资源体积要求。

## 5. 分类器接口

页面不直接依赖 fastText 的底层 API，使用项目内的异步适配接口：

```ts
type NearbyRestaurantClassification = {
  category: string;
  confidence: number;
  source: 'fasttext' | 'local-model' | 'fallback';
};

type NearbyRestaurantClassifier = {
  ready(): Promise<void>;
  classify(name: string, amapType: string): Promise<NearbyRestaurantClassification>;
};
```

适配层负责：

- 初始化 fastText WASM。
- 格式化名称和高德分类输入。
- 调用 `predict` 并读取最高概率结果。
- 校验标签并转换为应用分类结构。
- 捕获运行时异常并调用现有同步规则分类作为回退。

页面通过一个分类 hook 或等价的状态层批量处理前 20 家商家。分类任务必须支持结果顺序与商家 ID 对齐，不能因为单家预测失败而丢失整张列表。

## 6. 与微信小程序的兼容边界

Web 和小程序共用以下协议：

- 分类输入格式。
- 训练标签集合。
- 预测结果结构。
- 规则分类回退行为。

小程序端后续可以增加独立的 `WXWebAssembly` 运行时适配器，继续加载同一个 `.ftz` 文件。WASM 运行时文件需要按照小程序代码包或分包规则提供；模型文件可以随包提供，也可以通过配置过合法域名的 `wx.downloadFile` 下载，并保存到 `wx.env.USER_DATA_PATH` 缓存。

本阶段不在小程序端直接接入浏览器版 `fasttext.js`，因为官方 Web 版本依赖浏览器式模块和资源加载方式，小程序的 WASM 加载接口不同，必须单独封装并进行 Android、iOS 真机验证。

如果后续真机验证发现某些基础库或设备无法运行 WASM，小程序仍应使用同一个接口切换到后端分类或现有规则分类，不改变页面业务协议。

## 7. 失败与性能策略

- WASM 或模型加载失败不能阻塞搜索结果和页面渲染。
- 分类过程只处理前 20 家，不对隐藏候选执行模型推理。
- 通过 Promise 缓存保证运行时和模型只初始化一次。
- 单家预测失败时保留该商家的规则分类结果。
- 模型不放入应用启动必需的主逻辑，避免影响首页和普通游戏流程。
- 模型文件使用静态资源 URL，生产环境由浏览器 HTTP 缓存；后续如需主动版本控制，再增加带版本号的资源路径。

## 8. 测试与验收

必须覆盖：

- WASM 运行时可以加载 `.ftz` 模型并返回合法标签。
- 线上格式化输入与训练脚本格式一致，同时包含商家名称和高德分类。
- 前 20 家商家会得到 fastText 分类，21 家之后不会触发预测。
- fastText 返回的标签能够映射到应用大类。
- 模型加载期间页面仍有规则分类结果，不出现空白。
- 模型加载失败、预测失败和非法标签都会回退到规则分类。
- 同一页面不会重复初始化 WASM 或重复下载模型。
- 高德分类原文、评分、图片、列表顺序和现有游戏入口不变。
- 在 Chromium Web 开发环境中验证至少一组真实搜索结果，并记录模型分类效果，不能只用单元测试模拟结果。

## 9. 非目标

- 不重新训练模型或修改训练数据。
- 不在本阶段优化模型准确率。
- 不将智能分类重新用于附近菜品聚合。
- 不改变高德 API 请求参数。
- 不实现 ONNX、TinyBERT、Transformers.js 或小程序端 WASM 适配器。
