# 入口流程视觉与动效设计规格

日期：2026-08-13

状态：已确认设计，待实现

## 1. 目标与范围

本轮只优化以下 Web 流程的视觉质感、交互反馈和动效：

```text
首页 → 游戏模式选择 → 房间创建 / 加入 → 房间等待
```

目标是让用户感受到一个连续、轻快、有反馈的进入过程，而不是多个页面的瞬间硬切换。

本轮不改变：

- 房间、成员、轮次、数据集和身份的业务规则；
- 路由结构、API 请求参数和服务端状态；
- 页面文案的产品含义；
- 游戏主页已经验证过的滑卡交互；
- 当前品牌主色和整体页面结构。

## 2. 事实来源与视觉约束

产品行为继续以以下文档为准：

1. `docs/superpowers/specs/2026-08-12-food-game-e2e-design.md`；
2. `docs/superpowers/specs/2026-08-13-food-game-state-machine-design.md`；
3. 本文档只补充视觉和动效规则，不覆盖业务规则。

保留当前视觉基础：

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 页面背景 | `#F5F5F7` | 页面外层背景 |
| 主强调色 | `#FFD100` | 主按钮、选中态、品牌强调 |
| 深色操作色 | `#0F172A` | 组队按钮、房间主信息 |
| 表面色 | `#FFFFFF` | 卡片、弹窗、内容容器 |
| 次级文字 | `#64748B` | 说明、辅助状态 |
| 错误色 | `#F43F5E` | 输入错误和操作错误 |

视觉方向为“轻快有趣”：明黄色提供能量，深色表面提供稳定感，动画有轻微弹性但不使用夸张弹跳。

## 3. 动效原则

### 3.1 动效目的

每个动效必须属于以下目的之一：

- 反馈：确认按钮和输入操作已经被系统接收；
- 空间连续：说明页面、弹窗或列表项从哪里出现；
- 状态表达：说明创建中、加入中、等待中或选中态变化；
- 防止突兀：避免内容无过渡地出现或消失。

不为高频操作添加装饰性动画，也不因为“看起来酷”而移动功能性信息。

### 3.2 统一动效 token

在 `apps/web/src/shared/styles/index.css` 中提供全局 CSS token，所有入口流程动效使用这些 token，不在页面中重复定义曲线：

```css
:root {
  --ease-out: cubic-bezier(0.23, 1, 0.32, 1);
  --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
  --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
  --duration-press: 140ms;
  --duration-fast: 180ms;
  --duration-page: 220ms;
  --duration-dialog: 240ms;
}
```

具体规则：

- 进入和退出使用 `--ease-out`；
- 页面内移动或形变使用 `--ease-in-out`；
- 弹窗使用 `--ease-drawer` 或 Motion 的轻微 spring；
- 按钮按下反馈使用 100–160ms；
- 入口页面转场不超过 220ms；
- 弹窗不超过 240ms；
- 只动画 `transform` 和 `opacity`，不动画 `transition: all`、布局尺寸或间距；
- 不使用 `scale(0)`，进入初始值最低为 `scale(0.96)`；
- hover 动效必须放在 `(hover: hover) and (pointer: fine)` 媒体查询中；
- 必须提供 `prefers-reduced-motion: reduce` 的温和版本。

已有的 `motion` 包继续用于动态和可中断的 Motion 动画；简单的按钮、颜色和页面进入反馈优先使用 CSS。

## 4. 页面与组件设计

### 4.1 PageShell：统一页面进入感

`PageShell` 是入口流程的统一承载组件。页面内容挂载时使用轻微的 `opacity + translateY` 进入：

```text
初始：opacity 0, translateY(8px)
完成：opacity 1, translateY(0)
曲线：--ease-out
时长：--duration-page
```

页面进入动效不阻塞点击，不做跨路由等待，也不强制实现页面退出动画。这样可以保留路由的即时响应，并避免用户快速返回时被动画拖慢。

### 4.2 首页

首页保持当前白色大卡片和黄色 Logo，但增加一次性的层级进入节奏：

1. Logo 先进入，`scale(0.96) + opacity`，完成后保持静止；
2. 标题和副标题延迟 40ms 进入；
3. 用户名输入框延迟 80ms 进入；
4. 开始按钮延迟 120ms 进入。

每项只使用 `opacity + translateY(8px)`，不使用持续漂浮或循环动画。设置按钮只增加按下反馈，不增加持续旋转。

开始按钮：

- hover（仅鼠标）：背景色从 `#FFD100` 过渡到 `#FFC800`；
- active：`scale(0.98)`，`--duration-press`；
- 用户名错误时，错误信息通过 opacity 和轻微位移出现；不让整个表单抖动。

### 4.3 游戏模式选择页

模式卡片采用交错进入：

```text
说明文字：0ms
单人游戏：40ms
组队游戏：90ms
```

两张卡片使用相同的进入方向和曲线，避免页面出现两个不同的动效语言。

卡片交互：

- active：`scale(0.98)`，确认点击已经生效；
- hover（仅鼠标）：最多 `translateY(-2px)` 和背景色变化；
- 不在卡片上添加持续呼吸、旋转或大幅弹跳；
- 单人点击仍然立即进入数据集页面；
- 组队点击创建房间时，按钮进入明确的 submitting 状态，避免重复点击。

组队创建状态：

- 触发后保留当前卡片尺寸和布局；
- 文案或图标切换到“正在创建房间…”；
- 使用轻量 spinner 或 icon rotation 作为状态反馈，旋转只存在于 submitting 状态；
- 请求失败时恢复可点击状态，并在卡片下方显示现有错误信息。

### 4.4 房间页

房间页保持现有信息层级，重点增强状态变化：

#### 房间号卡片

进入时使用页面级进入动效，不再增加独立的大幅缩放。复制成功不改变业务，只显示短暂的复制反馈状态；反馈应在按钮内部完成，避免布局跳动。

#### 数据集选择

选中按钮使用背景色、文字色和轻微 `scale(0.98)` 的状态过渡。不可用的“周围菜品”保持静态禁用样式，不做晃动提示。

#### 操作按钮

- “加入房间”和“开始游戏”使用统一的 active press 反馈；
- 开始游戏请求期间保持按钮尺寸，显示 submitting 状态；
- 关闭/退出房间按钮不增加额外装饰动画，避免让危险操作显得像成功庆祝。

#### 成员列表

成员列表新增成员时使用：

```text
opacity 0 → 1
translateY(8px) → translateY(0)
duration: 180ms
curve: --ease-out
```

只为新增或移除的成员提供进入/退出反馈，不对每次房间快照刷新重新播放全部列表动画。成员列表是功能信息，禁止全量闪烁和循环动画。

### 4.5 加入房间弹窗

加入房间是偶发操作，允许标准弹窗动效：

- 背景层：opacity `0 → 1`，`--duration-dialog`；
- 弹窗：opacity `0 → 1`、`scale(0.96) → 1`、`translateY(8px) → 0`；
- 弹窗以 viewport 中心为 transform origin，这是模态框而不是触发器锚定 popover；
- 关闭时沿相同方向淡出，不使用 keyframes，保证快速打开/关闭可以被中断；
- 输入错误只在错误文本区域出现，不让弹窗整体抖动；
- submitting 状态保持弹窗尺寸和输入值不变。

取消和关闭按钮继续使用原有业务语义。动画不能阻塞键盘操作，也不能阻止 Escape 或显式取消动作（若当前组件已支持，则保持支持）。

## 5. 实现边界

允许修改：

- `apps/web/src/shared/styles/index.css`；
- `PageShell`、`BackButton`；
- 首页、模式页、房间页、加入房间弹窗；
- 入口流程所需的轻量共享动效组件或 class；
- 对上述页面的测试。

不在本轮修改：

- API、数据库、WebSocket、房间状态解析和错误分类；
- 游戏主页滑卡物理参数；
- 结果页业务逻辑；
- 新增动画库、UI 组件库或状态机库；
- 菜品数据和图片资源。

## 6. 可访问性与性能

- `prefers-reduced-motion: reduce` 下保留必要的 opacity/color 反馈，移除位移、旋转、弹性和持续动画；
- hover 只对支持 hover 的精确指针设备生效；
- 所有按钮保留现有 focus-visible 样式，并确保 submitting/disabled 状态有可读文本或 aria 状态；
- 动画只使用 transform、opacity、颜色或必要的 clip-path；
- 不通过父元素 CSS 变量驱动大量子节点 transform；
- 动效不改变页面布局尺寸，不制造滚动条闪动；
- 旧浏览器不支持 `@starting-style` 时必须仍然有可用的静态首屏。

## 7. 验收标准

功能和业务：

- 首页仍可编辑用户名并进入模式选择；
- 单人游戏仍直接进入数据集选择；
- 组队游戏仍创建房间并进入房间页；
- 房主仍可切换数据集、打开加入房间弹窗和开始游戏；
- 客人仍只能查看数据集、等待房主开始和退出房间；
- 加入房间校验、错误处理和现有 API 调用不改变。

视觉和动效：

- 首页、模式页、房间页首次进入有统一且不阻塞操作的进入反馈；
- 模式卡片、房间操作按钮和弹窗有一致的按压反馈；
- 加入房间弹窗不会瞬间出现或消失；
- 成员列表只对实际新增/移除成员播放一次反馈，不因刷新闪烁；
- 创建房间、开始游戏和加入房间请求期间有明确的 loading 状态；
- reduced-motion 下无明显位移、旋转或弹性动画；
- 使用真实浏览器在桌面和移动视口检查动画节奏，重点检查快速点击、快速打开/关闭弹窗和多人成员刷新。

## 8. 验证计划

实现完成后执行：

```bash
pnpm lint
NODE_OPTIONS=--localstorage-file=/tmp/lets-eat-vitest.json pnpm test
pnpm build
git diff --check
```

此外使用浏览器手动检查：

1. 首页进入和用户名错误反馈；
2. 单人/组队卡片的按压与组队创建 loading；
3. 房主打开、取消、提交加入房间弹窗；
4. 两个浏览器中客人加入后成员列表只新增一次；
5. 浏览器设置 reduced motion 后所有入口流程仍然可操作。
