# Web 附近餐饮搜索 MVP 规格

日期：2026-08-30
状态：附近搜索 MVP 已实现；2026-09-07 开启评分排序实验，已接入附近门店单人游戏；2026-09-12 增加 Web 端前 20 家商家名称智能菜品类型预览

## 1. 文档目的

本文档描述 Web 版“周围菜品”功能的第一版实现规则，作为后续开发、测试和验收依据。

本功能是当前固定菜品库之外的一个单人游戏入口。它只影响 Web 版，不修改微信小程序，也不改变多人游戏的现有规则。

## 2. 产品目标

用户可以通过浏览器定位或手动选点，搜索指定范围内评分较高的餐饮 POI，并在列表中直接查看评分最高的附近门店。

第一版只验证以下闭环：

1. 用户配置高德 Key。
2. 用户获取当前位置，或在地图上手动选择位置。
3. 用户设置搜索范围和门店数量并重新搜索。
4. 页面展示最多 10、20 或 30 家附近餐厅的名称、餐饮类型和高德评分，默认 20 家。
5. 只保留附近评分有效且最高的用户选择数量的门店。
6. 评分缺失或无效的门店不进入本次实验列表；有效评分不足所选数量时展示实际数量。
7. 至少有 3 家门店时，可以直接进入单人滑卡；每家门店对应一张卡，不进行菜品大类聚合。

## 3. 范围与限制

### 3.1 包含

- Web 版菜品数据集页启用“周围菜品”。
- 设置页增加高德配置区域。
- 浏览器定位。
- 高德地图 JS API 地图选点。
- 高德周边搜索 API 查询餐饮 POI。
- 搜索范围选择：500 米、1 公里、2 公里、3 公里、5 公里。
- 门店数量选择：10 家、20 家、30 家，默认 20 家。
- 高德周边搜索候选结果中评分最高的用户选择数量的门店。
- 结果不足 3 家时显示数量提示并禁用开始游戏。
- 搜索结果的本地会话缓存和刷新恢复。
- 按评分筛选附近门店列表；本实验不生成菜品大类卡片。
- 开局时使用高德返回的门店图片；缺图或加载失败时使用内置品牌封面。
- 对当前结果列表前 20 家商家增加基于名称的本地智能菜品类型预览；不改写高德分类，不影响游戏流程。

### 3.2 不包含

- 微信小程序同步实现。
- 多人房间使用附近餐厅。
- 后端保存附近搜索结果。
- 餐厅评分、评论、导航、下单或外卖跳转。
- 用户可见的搜索结果分页或获取全部餐厅。
- 搜索结果分类统计面板。
- 用户自定义餐厅编辑。

## 4. 高德服务方案

第一版按用户确认的最简单方案使用一套高德 Key：

- 高德 JS API：加载地图、地图拖动和地图选点。
- 高德 JS API 的 `PlaceSearch` 插件：查询餐饮 POI，不直接使用需要“Web 服务”类型 Key 的 REST 接口。
- `securityJsCode`：用于高德 JS API 的加载配置。
- Key 和 `securityJsCode` 均由用户在 Web 设置页维护，并保存在当前设备。

代码不新增第二个 Key 配置项。地图与周边搜索统一使用“Web 端（JS API）”Key 和 `securityJsCode`；调用失败时必须展示明确错误，不得伪造搜索结果。

### 4.1 周边查询参数

第一版使用周边查询接口，核心参数如下：

```text
PlaceSearch.type = 050000
PlaceSearch.pageSize = 50
PlaceSearch.pageIndex = 1..4
PlaceSearch.extensions = all
searchNearBy.center = [longitude, latitude]
searchNearBy.radius = 当前搜索范围，单位米
```

其中 `050000` 表示餐饮服务。实验会读取最多 4 页、最多 200 个候选 POI，再按可解析的高德评分降序排列，最终只保留前 `resultLimit` 家（10、20 或 30）；同分时保持高德返回顺序。高德返回不足一页时提前结束翻页。

## 5. 页面与路由流程

### 5.1 菜品数据集页

“周围菜品”从待上线状态变为可用入口。

- 有完整高德配置：直接进入周围菜品搜索页。
- 没有高德配置：进入设置页的高德配置区域。
- 从设置页保存成功后，返回周围菜品搜索页并自动定位、搜索。

### 5.2 设置页

增加“高德地图配置”区域，包含：

- 高德 Key：完整显示，可编辑。
- `securityJsCode`：完整显示，可编辑。
- 保存按钮。

设置页是唯一的高德配置编辑入口。搜索页不提供 Key 或安全密钥编辑表单，只在配置无效时提供“前往设置”操作。

从首页设置入口进入并保存时，保存成功后留在设置页；从周围菜品流程跳转进入时，保存成功后返回周围菜品搜索页。

### 5.3 周围菜品搜索页

页面不展示地图，只展示搜索和结果内容：

- 页面标题“周围菜品”。
- 当前搜索位置状态。
- “更换位置”按钮。
- 搜索范围选择器，默认 2 公里。
- 门店数量选择器，默认 20 家。
- “定位到我”和“重新搜索”作为并排的普通操作按钮。
- 搜索结果数量，例如“找到 12 家餐厅”。
- 餐厅列表，最多为所选的 10、20 或 30 条，按评分从高到低排列。
- “开始游戏”按钮。
- “退出周围菜品”按钮。

餐厅列表只展示：

- 餐厅名称。
- 高德餐饮类型。
- 智能菜品类型；显示在高德餐饮类型下方，无法可靠判断时显示“其他”。
- 高德评分；没有有效评分的门店不展示。

智能菜品类型规则：

- 只处理当前结果列表前 20 家商家名称。
- 使用 Web 端本地轻量字符 n-gram 分类器，不发起额外网络请求。
- 智能分类仅用于列表展示，本次不改变评分排序、游戏卡片、附近商家一对一进入游戏的规则。

不展示地址、距离、电话、营业时间等字段，但这些字段可以保存在本地数据模型中。

搜索范围改变后不自动请求；只有点击“重新搜索”才发起搜索。首次进入搜索页时，在位置准备完成后自动搜索。

页面布局顺序为：搜索范围和门店数量、“定位到我”和“重新搜索”操作按钮、“开始游戏”和“退出周围菜品”操作按钮、搜索结果摘要、门店列表。操作按钮固定放在门店列表上方，不随门店列表长度被推到页面底部。退出按钮使用深色操作色背景和白色文字。

改变搜索范围或门店数量后不自动请求；只有点击“重新搜索”才应用新的配置并发起搜索。“定位到我”独立重新请求浏览器当前位置，并使用当前搜索范围和门店数量立即查询附近餐厅。定位期间锁定定位、重新搜索和开始游戏操作；定位失败时保留当前搜索结果并显示明确错误，用户可以重试或进入地图选点页。

### 5.4 地图选点页

地图选点页是独立页面，用于定位失败和主动更换位置。

页面包含：

- 顶部返回按钮。
- 高德地图。
- 固定在视图中心的十字标记。
- 地图拖动能力。
- 底部“使用此位置”按钮。

用户拖动地图调整中心点；点击“使用此位置”后返回搜索页并使用该中心点搜索。

当浏览器定位失败时：

1. 如果存在上一次成功位置，以该位置为地图初始中心。
2. 如果不存在上一次成功位置，显示省 / 市两级选择器，用户选择城市后以城市中心为地图初始中心。
3. 用户仍然可以继续拖动地图微调位置。

不加入区县选择，不使用地图任意点击作为选点方式。

### 5.5 单人游戏与结果页

当前评分排序实验中，“开始游戏”不读取固定菜品库，也不进行餐厅聚合；每家有效评分门店直接作为一张附近门店卡进入现有单人滑卡和结果流程。

评分筛选规则：

- 先获取周边搜索候选结果，再从高德返回的有效评分中按数值降序排列。
- 评分相同时保持高德候选顺序，避免引入额外的主观排序。
- 评分缺失、无法解析或不在有效范围内的门店不进入列表。
- 最终只保存和展示评分最高的 `resultLimit` 家有效门店；开局时每家门店转换为一张游戏卡，优先使用高德图片，缺图或加载失败时回退到内置品牌封面，并保留门店名称。

结果页返回操作回到游戏模式选择页或现有单人流程的既定返回位置，不进入多人房间。

## 6. 位置获取规则

位置优先级如下：

1. 当前浏览器定位成功的位置。
2. 当前设备上一次成功的位置。
3. 用户通过省 / 市选择后确定的城市中心，再由地图拖动微调。

成功使用新位置搜索后，更新上一次成功位置缓存。

定位失败、用户拒绝权限、浏览器不支持定位和定位超时都必须进入可恢复的地图选点流程，不得直接让页面卡死或无限重试。

## 7. 数据模型

界面展示模型与本地保存模型分离。附近餐厅保存为：

```ts
type NearbyRestaurant = {
  source: 'amap';
  id: string;
  name: string;

  type: string;
  typeCode?: string;
  categoryPath?: string[];

  location?: {
    longitude: number;
    latitude: number;
  };
  entranceLocation?: {
    longitude: number;
    latitude: number;
  };
  distanceMeters?: number;
  rating?: number;
  imageUrl?: string;

  // 智能分类仅在展示层派生，NearbyRestaurant 不保存该字段。

  address?: string;
  province?: string;
  provinceCode?: string;
  city?: string;
  cityCode?: string;
  district?: string;
  districtCode?: string;

  businessArea?: string;
  telephone?: string;
  website?: string;
  email?: string;
  businessHours?: string;
  businessStatus?: string;

  fetchedAt: string;
  providerData?: unknown;
};
```

约束：

- 高德没有返回的字段保持为空，不补造。
- `type` 保留高德原始分类路径。
- `categoryPath` 从分类路径拆分得到，例如 `餐饮服务;中餐厅;粤菜馆` 转为数组。
- `providerData` 保留对应的高德原始 POI 数据，暂不直接展示。
- `rating` 统一为可选数字，来源优先读取高德餐饮深度信息中的评分，并保留原始 `providerData`。
- `imageUrl` 优先读取高德餐饮深度信息 `photos` 中第一张有效的 HTTP(S) 图片地址；没有有效图片时保持为空，并保留原始 `providerData`。
- 智能菜品类型由附近 Web 页面使用本地分类器从商家名称派生，不覆盖 `type`、`typeCode` 或 `categoryPath`；置信度不足时显示“其他”。
- 开始游戏时，每家门店转换为一张 `FoodChoice` 游戏卡并保存附近游戏回合，不进行菜品大类聚合。

## 8. 本地缓存

### 8.1 localStorage

保存：

- 高德 Key。
- `securityJsCode`。
- 上一次成功使用的位置。

高德配置只保存在当前浏览器，不发送到 Lets Eat 自有后端。

### 8.2 sessionStorage

保存本次附近搜索会话：

- 搜索中心坐标。
- 搜索半径。
- 10、20 或 30 的 `resultLimit`。
- 搜索时间。
- 最多 30 条完整 `NearbyRestaurant` 数据。
- 原始高德 POI 数据。

开始附近游戏后，额外保存门店列表对应的游戏卡、随机后的卡片顺序、选择决策和完成状态。

刷新页面时恢复当前会话；关闭标签页后由浏览器清理。不把附近餐厅数据写入后端，也不跨设备同步。

## 9. 状态与容错

搜索页至少需要覆盖以下状态：

- `missing-config`：未配置 Key，跳转设置页。
- `locating`：正在获取浏览器位置。
- `location-ready`：已经取得可用位置。
- `location-fallback`：使用缓存位置或省市中心，提示用户可更换位置。
- `searching`：正在请求周边餐饮。
- `success`：返回 1～所选数量家餐厅。
- `empty`：没有餐厅结果。
- `insufficient`：返回 1～2 家，显示有效评分门店不足提示并禁止开始游戏。
- `ready`：返回至少 3 家，允许开始附近门店游戏。
- `invalid-config`：Key 或安全配置无效，提供“前往设置”。
- `network-error`：网络或跨域请求失败，提供“重新搜索”。
- `location-error`：定位失败，提供“地图选点”。

错误处理要求：

- 使用现有 Toast / Confirm 组件，不使用系统 `alert`。
- 不因一次搜索失败清空上一次有效结果，除非用户明确退出本次流程。
- “重新搜索”请求期间锁定重复点击。
- 改变搜索范围或门店数量后，在重新搜索前禁用开始游戏，并提示先重新搜索。
- 搜索结果不足 3 家时保留结果，让用户调整范围后重新搜索。
- “退出周围菜品”返回菜品数据集页，不清除高德配置和上一次位置。

## 10. 组件和代码边界

- 高德 SDK 加载、地图选点和 POI 请求封装在 Web 专用 nearby feature 中。
- 不把浏览器专用的高德逻辑放进微信小程序代码或跨平台核心逻辑。
- POI 原始数据到 `NearbyRestaurant` 的归一化、评分读取和排序逻辑保持在 nearby feature 内并可单元测试。
- 附近门店到 `FoodChoice` 的转换保持一对一，只负责游戏卡字段映射，不进行菜品大类聚合。
- 游戏卡优先使用 `imageUrl`，图片加载失败时由通用图片组件回退到内置品牌封面。
- 页面只负责状态展示和用户操作，缓存、定位、请求和数据归一化分别放在对应模块。
- 优先复用项目已有的路由、Toast、Confirm、滑卡和品牌占位图能力。
- 商家名称智能分类保持在 nearby feature 内，页面只消费分类结果，不在组件中实现分类规则。

## 11. 验收标准

### 配置与入口

- 未配置 Key 时，从菜品数据集页进入设置页。
- 保存配置后自动回到周围菜品搜索页并开始定位。
- 已配置 Key 时可以直接进入周围菜品搜索页。
- 设置页可以完整查看和修改 Key、`securityJsCode`。

### 位置与搜索

- 浏览器定位成功后自动完成一次周边搜索。
- 搜索页可以通过“定位到我”重新获取浏览器当前位置并立即搜索。
- 主动定位失败时保留已有结果，不静默改用缓存位置。
- 定位失败时可以进入地图选点页并完成手动选点。
- 有缓存位置时地图以缓存位置为初始中心。
- 无缓存位置时可以选择省 / 市两级城市中心。
- 改变搜索范围后，只有点击“重新搜索”才请求接口。
- 查询使用餐饮类型和指定半径，读取最多 200 个候选结果后按评分排序，页面按 10、20 或 30 的选择展示有效评分门店。
- 当前结果列表前 20 家商家在高德分类下方显示本地智能菜品类型；智能分类失败时显示“其他”，不影响列表和游戏。

### 游戏

- “开始游戏”按钮保留在搜索范围下方；至少 3 家门店且搜索范围没有待更新时启用。
- 当前实验不读取固定菜品库、不进行菜品大类聚合；每家门店直接进入现有单人滑卡和结果页。
- 附近菜品流程不影响多人房间和微信小程序。

### 容错与缓存

- 无结果、接口错误、Key 错误和定位失败都有可恢复操作。
- 刷新搜索页后可以恢复本次 `sessionStorage` 搜索结果。
- 搜索结果不写入后端。
- 小程序目录和小程序构建产物不发生改动。
