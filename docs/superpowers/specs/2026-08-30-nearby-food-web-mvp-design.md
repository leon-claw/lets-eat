# Web 附近餐饮搜索 MVP 规格

日期：2026-08-30
状态：已确认设计，待实现

## 1. 文档目的

本文档描述 Web 版“周围菜品”功能的第一版实现规则，作为后续开发、测试和验收依据。

本功能是当前固定菜品库之外的一个单人游戏入口。它只影响 Web 版，不修改微信小程序，也不改变多人游戏的现有规则。

## 2. 产品目标

用户可以通过浏览器定位或手动选点，搜索指定范围内综合排序靠前的餐饮 POI，并直接使用搜索结果进行一次单人左右滑动选菜。

第一版只验证以下闭环：

1. 用户配置高德 Key。
2. 用户获取当前位置，或在地图上手动选择位置。
3. 用户设置搜索范围并重新搜索。
4. 页面展示最多 20 家附近餐厅的名称和餐饮类型。
5. 至少有 3 家餐厅时进入现有单人选菜流程。
6. 选菜结束后复用现有单人结果页。

## 3. 范围与限制

### 3.1 包含

- Web 版菜品数据集页启用“周围菜品”。
- 设置页增加高德配置区域。
- 浏览器定位。
- 高德地图 JS API 地图选点。
- 高德周边搜索 API 查询餐饮 POI。
- 搜索范围选择：500 米、1 公里、2 公里、3 公里、5 公里。
- 高德综合排序前 20 家结果。
- 结果不足 3 家时阻止开始游戏。
- 搜索结果的本地会话缓存和刷新恢复。
- 将附近餐厅适配为现有单人滑卡数据。

### 3.2 不包含

- 微信小程序同步实现。
- 多人房间使用附近餐厅。
- 后端保存附近搜索结果。
- 餐厅评分、评论、导航、下单或外卖跳转。
- 搜索结果分页或获取全部餐厅。
- 搜索结果分类统计面板。
- 用户自定义餐厅编辑。

## 4. 高德服务方案

第一版按用户确认的最简单方案使用一套高德 Key：

- 高德 JS API：加载地图、地图拖动和地图选点。
- 高德周边搜索 API：查询餐饮 POI。
- `securityJsCode`：用于高德 JS API 的加载配置。
- Key 和 `securityJsCode` 均由用户在 Web 设置页维护，并保存在当前设备。

代码不新增第二个 Key 配置项。高德控制台的服务权限和实际可用性以运行时返回为准；调用失败时必须展示明确错误，不得伪造搜索结果。

### 4.1 周边查询参数

第一版使用周边查询接口，核心参数如下：

```text
location = longitude,latitude
types = 050000
radius = 当前搜索范围，单位米
sortrule = weight
offset = 20
page = 1
extensions = all
```

其中 `050000` 表示餐饮服务，`weight` 表示高德综合排序。页面文案使用“综合排序”，不把它描述为用户评分或真实口碑排名。

第一版只读取第一页，不翻页；高德返回少于 20 条时使用实际返回数量。

## 5. 页面与路由流程

### 5.1 菜品数据集页

“周围菜品”从待上线状态变为可用入口。

- 有完整高德配置：直接进入周围菜品搜索页。
- 没有高德配置：进入设置页的高德配置区域。
- 从设置页保存成功后，返回周围菜品搜索页并自动定位、搜索。

### 5.2 设置页

增加“高德地图配置”区域，包含：

- 高德 Key：完整显示，可编辑。
- `securityJsCode`：完整显示，可编辑。
- 保存按钮。

设置页是唯一的高德配置编辑入口。搜索页不提供 Key 或安全密钥编辑表单，只在配置无效时提供“前往设置”操作。

从首页设置入口进入并保存时，保存成功后留在设置页；从周围菜品流程跳转进入时，保存成功后返回周围菜品搜索页。

### 5.3 周围菜品搜索页

页面不展示地图，只展示搜索和结果内容：

- 页面标题“周围菜品”。
- 当前搜索位置状态。
- “更换位置”按钮。
- 搜索范围选择器，默认 2 公里。
- “重新搜索”按钮。
- 搜索结果数量，例如“找到 12 家餐厅”。
- 餐厅列表，最多 20 条。
- “开始游戏”按钮。
- “退出周围菜品”按钮。

餐厅列表只展示：

- 餐厅名称。
- 餐饮类型。

不展示地址、距离、电话、营业时间、评分等字段，但这些字段可以保存在本地数据模型中。

搜索范围改变后不自动请求；只有点击“重新搜索”才发起搜索。首次进入搜索页时，在位置准备完成后自动搜索。

### 5.4 地图选点页

地图选点页是独立页面，用于定位失败和主动更换位置。

页面包含：

- 顶部返回按钮。
- 高德地图。
- 固定在视图中心的十字标记。
- 地图拖动能力。
- 底部“使用此位置”按钮。

用户拖动地图调整中心点；点击“使用此位置”后返回搜索页并使用该中心点搜索。

当浏览器定位失败时：

1. 如果存在上一次成功位置，以该位置为地图初始中心。
2. 如果不存在上一次成功位置，显示省 / 市两级选择器，用户选择城市后以城市中心为地图初始中心。
3. 用户仍然可以继续拖动地图微调位置。

不加入区县选择，不使用地图任意点击作为选点方式。

### 5.5 单人游戏与结果页

点击“开始游戏”后：

- 结果少于 3 家时按钮禁用，并提示“至少需要 3 家餐厅才能开始游戏”。
- 结果达到 3 家时，使用当前搜索结果进入现有单人游戏主页。
- 开始前在本地随机打乱餐厅顺序。
- 使用现有的跟手左右滑动、飞出和撤销交互。
- 使用统一品牌占位图，不为餐厅生成或假造图片。
- 卡片展示餐厅名称和餐饮类型；不展示虚构的菜品描述。
- 结束后进入现有单人结果页。

结果页返回操作回到游戏模式选择页或现有单人流程的既定返回位置，不进入多人房间。

## 6. 位置获取规则

位置优先级如下：

1. 当前浏览器定位成功的位置。
2. 当前设备上一次成功的位置。
3. 用户通过省 / 市选择后确定的城市中心，再由地图拖动微调。

成功使用新位置搜索后，更新上一次成功位置缓存。

定位失败、用户拒绝权限、浏览器不支持定位和定位超时都必须进入可恢复的地图选点流程，不得直接让页面卡死或无限重试。

## 7. 数据模型

界面展示模型与本地保存模型分离。附近餐厅保存为：

```ts
type NearbyRestaurant = {
  source: 'amap';
  id: string;
  name: string;

  type: string;
  typeCode?: string;
  categoryPath?: string[];

  location?: {
    longitude: number;
    latitude: number;
  };
  entranceLocation?: {
    longitude: number;
    latitude: number;
  };
  distanceMeters?: number;

  address?: string;
  province?: string;
  provinceCode?: string;
  city?: string;
  cityCode?: string;
  district?: string;
  districtCode?: string;

  businessArea?: string;
  telephone?: string;
  website?: string;
  email?: string;
  businessHours?: string;
  businessStatus?: string;

  fetchedAt: string;
  providerData?: unknown;
};
```

约束：

- 高德没有返回的字段保持为空，不补造。
- `type` 保留高德原始分类路径。
- `categoryPath` 从分类路径拆分得到，例如 `餐饮服务;中餐厅;粤菜馆` 转为数组。
- `providerData` 保留对应的高德原始 POI 数据，暂不直接展示。
- 适配现有游戏时，只使用 `id`、`name`、`type` 和品牌占位图。

## 8. 本地缓存

### 8.1 localStorage

保存：

- 高德 Key。
- `securityJsCode`。
- 上一次成功使用的位置。

高德配置只保存在当前浏览器，不发送到 Lets Eat 自有后端。

### 8.2 sessionStorage

保存本次附近搜索会话：

- 搜索中心坐标。
- 搜索半径。
- 搜索时间。
- 最多 20 条完整 `NearbyRestaurant` 数据。
- 原始高德 POI 数据。

刷新页面时恢复当前会话；关闭标签页后由浏览器清理。不把附近餐厅数据写入后端，也不跨设备同步。

## 9. 状态与容错

搜索页至少需要覆盖以下状态：

- `missing-config`：未配置 Key，跳转设置页。
- `locating`：正在获取浏览器位置。
- `location-ready`：已经取得可用位置。
- `location-fallback`：使用缓存位置或省市中心，提示用户可更换位置。
- `searching`：正在请求周边餐饮。
- `success`：返回 1～20 家餐厅。
- `empty`：没有餐厅结果。
- `insufficient`：返回 1～2 家，禁止开始游戏。
- `ready`：返回至少 3 家，可以开始游戏。
- `invalid-config`：Key 或安全配置无效，提供“前往设置”。
- `network-error`：网络或跨域请求失败，提供“重新搜索”。
- `location-error`：定位失败，提供“地图选点”。

错误处理要求：

- 使用现有 Toast / Confirm 组件，不使用系统 `alert`。
- 不因一次搜索失败清空上一次有效结果，除非用户明确退出本次流程。
- “重新搜索”请求期间锁定重复点击。
- 搜索结果不足 3 家时保留结果，让用户调整范围后重新搜索。
- “退出周围菜品”返回菜品数据集页，不清除高德配置和上一次位置。

## 10. 组件和代码边界

- 高德 SDK 加载、地图选点和 POI 请求封装在 Web 专用 nearby feature 中。
- 不把浏览器专用的高德逻辑放进微信小程序代码或跨平台核心逻辑。
- POI 原始数据到 `NearbyRestaurant` 的归一化逻辑保持纯函数，便于单元测试。
- 附近餐厅到现有 `FoodChoice` 的转换使用单独适配器，不改变固定菜品库的数据结构。
- 页面只负责状态展示和用户操作，缓存、定位、请求和数据归一化分别放在对应模块。
- 优先复用项目已有的路由、Toast、Confirm、滑卡和品牌占位图能力。

## 11. 验收标准

### 配置与入口

- 未配置 Key 时，从菜品数据集页进入设置页。
- 保存配置后自动回到周围菜品搜索页并开始定位。
- 已配置 Key 时可以直接进入周围菜品搜索页。
- 设置页可以完整查看和修改 Key、`securityJsCode`。

### 位置与搜索

- 浏览器定位成功后自动完成一次周边搜索。
- 定位失败时可以进入地图选点页并完成手动选点。
- 有缓存位置时地图以缓存位置为初始中心。
- 无缓存位置时可以选择省 / 市两级城市中心。
- 改变搜索范围后，只有点击“重新搜索”才请求接口。
- 查询使用餐饮类型、指定半径、综合排序，并最多取得 20 条第一页结果。

### 游戏

- 结果少于 3 家时无法开始，并给出明确提示。
- 结果至少 3 家时进入现有单人滑卡页面。
- 餐厅顺序在开始游戏前本地随机化。
- 选菜结束后进入现有单人结果页。
- 附近菜品流程不影响多人房间和微信小程序。

### 容错与缓存

- 无结果、接口错误、Key 错误和定位失败都有可恢复操作。
- 刷新搜索页后可以恢复本次 `sessionStorage` 搜索结果。
- 搜索结果不写入后端。
- 小程序目录和小程序构建产物不发生改动。
