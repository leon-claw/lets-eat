# Web 附近商家智能菜品类型设计

日期：2026-09-12

状态：已确认，Web 已实现

## 1. 目标

在 Web 版“周围菜品”搜索结果中，为当前展示的前 20 家商家增加一行基于商店名称和高德原始分类推断的菜品类型。高德原始分类继续保留并显示在上方，智能分类显示在下方；本次只做列表预览，不改变搜索排序、游戏卡片、多人流程或微信小程序。

## 2. 用户可见行为

每家商家按以下顺序展示：

```text
商家名称                         评分
高德分类：餐饮服务 · 中餐厅
智能分类：火锅
```

- 智能分类只处理结果列表前 20 家，不请求或分类第 21 家之后的隐藏候选。
- 当前结果列表仍保持现有评分排序和数量选择行为；默认展示 20 家时，20 家全部显示智能分类。
- 智能分类不覆盖、不改写高德 `type`、`typeCode` 或 `categoryPath`。
- 只能判断到用户定义的大类时显示对应大类；无法可靠判断时显示“其他”。
- 不在界面显示模型置信度、原始关键词或模型技术名称。

## 3. 分类目标

分类标签使用应用现有的大类菜品 ID / 显示名称，包括已确认的火锅，以及中餐、川菜、粤菜、日料、西餐、咖啡、茶饮、甜品等现有大类。分类器必须包含“其他”兜底标签。

第一版输入包含商家名称和高德原始 `type`。名称中的中文字符、英文品牌词、数字和常见餐饮后缀，以及高德分类中的具体菜系词都可以作为特征；“中餐厅”“外国餐厅”等过于宽泛的高德分类不单独下结论。名称特征权重高于高德分类，避免把高德的粗分类放大为错误结论。

## 4. 分类器方案

采用纯 TypeScript 可执行的字符 n-gram 线性分类器：

1. 对商家名称和高德 `type` 做稳定归一化：去除首尾空白、统一大小写、压缩连续空格和常见标点。
2. 从归一化名称提取字符 unigram、bigram 和有限的关键词特征；从高德 `type` 提取有限的具体菜系特征。
3. 对每个大类累加对应权重，名称特征权重更高，取最高分作为预测结果。
4. 计算最高分与次高分之间的差距作为置信度依据。
5. 低于阈值、输入为空或只有宽泛高德分类时返回“其他”。

模型权重和标签映射是只读前端资源，不引入外部网络请求，不引入 ONNX、TensorFlow.js 或大语言模型依赖。分类器通过纯函数暴露，后续可以替换为真正训练导出的权重文件而不改变页面接口。

分类结果使用明确的数据结构：

```ts
type NearbyRestaurantClassification = {
  category: string;
  confidence: number;
  source: 'local-model' | 'fallback';
};
```

## 5. 代码边界与数据流

```text
高德搜索结果
  → 现有评分排序和数量截取
  → 前 20 家商家名称 + 高德 type
  → nearby-food 本地分类器
  → 页面同时展示高德分类和智能分类
```

- 分类器放在 `apps/web/src/features/nearby-food` 内，保持 Web 专用。
- `NearbyRestaurant` 不保存推断字段；第一版由列表展示层按当前结果派生，避免改变已有 sessionStorage 数据协议和多人/游戏数据结构。
- `nearby-food-adapter.ts` 不改动，附近商家仍然一对一转换为游戏卡片。
- `NearbyFoodPage.tsx` 只负责将分类结果呈现为第二行，不在组件中实现分类规则。
- 列表顺序、评分排序、开始游戏和游戏卡片布局保持不变。

## 6. 失败与兜底

- 分类器异常、空名称、无法匹配或置信度不足时返回“其他”，不能阻断商家列表。
- 分类结果不影响搜索成功状态，也不影响开始游戏按钮。
- 模型权重属于静态代码资源，不需要单独下载、缓存或版本协商。
- 页面仍然显示高德分类；“其他”只代表智能分类无法可靠判断，不代表高德没有分类。

## 7. 测试与验收

必须覆盖：

- 火锅、日料、咖啡、西餐等带明显名称信号的商家能得到对应分类。
- “老地方食府”“某某餐饮”等信息不足的名称得到“其他”。
- 分类函数不修改输入对象，结果包含合法分类、置信度和来源。
- 页面只对前 20 家结果生成智能分类，并在高德分类下方展示。
- 具体高德分类可以辅助名称信息不足的商家得到对应分类，宽泛高德分类不会单独强行分类。
- 高德分类仍按原始字符串展示。
- 搜索列表顺序、评分、图片和开始游戏行为没有变化。

## 8. 非目标

- 不在本次实现真实 ONNX / TinyBERT / TextCNN 推理。
- 不修改高德请求参数和评分排序。
- 不改变 10 / 20 / 30 数量选择器的既有搜索协议。
- 不修改微信小程序端。
- 不将智能分类用于附近菜品聚合或改变游戏卡片数量。
