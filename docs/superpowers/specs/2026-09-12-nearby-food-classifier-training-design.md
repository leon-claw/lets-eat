# 周围商家分类训练数据与 fastText 实验设计

日期：2026-09-12

状态：已确认的离线实验设计

## 1. 目标

为 Web 版周围商家分类建立一条可复现的离线训练流程：使用商家名称和高德原始分类作为输入，生成 1000 条带业务标签的训练样本，训练 fastText 字符 n-gram 分类器，并输出可审查的数据集、模型和评估报告。

本实验用于判断“训练模型”是否比当前手工规则更适合识别商家菜品大类，不直接改变线上分类逻辑。

## 2. 当前标签集合

训练标签与当前 Web 分类器保持一致：

- 粤菜
- 川菜
- 湘菜
- 火锅
- 烧烤
- 螺蛳粉
- 日料
- 韩餐
- 西餐
- 东南亚菜
- 东北菜
- 云南菜
- 面食
- 轻食
- 甜品奶茶
- 海鲜
- 其他

数据集固定为 1000 条：16 个业务大类各 55 条，「其他」120 条。

## 3. 输入与数据格式

每条样本包含以下字段：

```json
{
  "id": "sample-0001",
  "label": "火锅",
  "name": "蜀大侠火锅",
  "amap_type": "餐饮服务|中餐厅|火锅店",
  "source": "synthetic",
  "pattern": "brand_and_type"
}
```

训练文本使用字段前缀区分来源，避免模型把高德分类误当成商家名称：

```text
__label__火锅 name_蜀大侠火锅 amap_餐饮服务 中餐厅 火锅店
```

JSONL 是审查和后续追加真实标注的主格式；fastText 文本是由脚本生成的训练输入，不手工维护两份数据。

## 4. 数据生成原则

- 使用固定随机种子，保证每次生成结果一致。
- 每个业务大类覆盖明确菜名、品牌/店名、店型、地域词和弱提示组合。
- 「其他」覆盖宽泛高德分类、无菜品语义的生活方式门店、综合餐饮名称、重复或无法可靠判断的名称。
- 同一条样本只能有一个主标签，和线上分类保持一致。
- 生成后校验总数、类别数量、ID 唯一性、文本非空和标签合法性。
- 去除完全重复样本；不把同一个模板字符串重复填充作为有效样本。

## 5. 数据划分与评估

按类别分层、固定随机种子划分 80% 训练集、10% 验证集和 10% 测试集。报告至少包含：

- 总体准确率；
- 宏平均 precision、recall、F1；
- 每个标签的 precision、recall、F1 和样本数；
- 混淆矩阵；
- 预测置信度低于阈值时的覆盖率与「其他」比例。

合成数据评估只代表流程和标签可分性，不能代表真实高德数据的线上效果。报告必须明确标注数据来源为 synthetic。

## 6. 训练方案

第一版使用 fastText supervised 训练，优先使用字符 n-gram 以适配中文短名称，并保留高德分类字段作为辅助特征。模型使用较小的维度和 bucket，训练完成后额外导出量化模型，比较原始模型和量化模型的体积及测试指标。

训练参数由脚本集中定义，避免命令行参数漂移。若本机未安装 fastText，脚本应给出明确安装提示，而不是生成伪模型或静默跳过训练。

## 7. 输出目录

实验产物放在 `apps/web/src/features/nearby-food/training/` 下：

- `data/nearby-restaurant-classification.jsonl`：完整标注数据；
- `data/train.txt`、`data/validation.txt`、`data/test.txt`：fastText 输入文件；
- `models/nearby-restaurant-classifier.bin`：原始模型；
- `models/nearby-restaurant-classifier.ftz`：量化模型；
- `reports/evaluation.json`：机器可读评估结果；
- `reports/evaluation.md`：人工可读报告。

生成器、数据校验器和评估器保留在 `scripts/nearby-classifier/`，后续可以用真实高德数据替换 synthetic 数据源而不改变训练流程。

## 8. 非目标

- 本次不把模型打包进 Web 页面。
- 本次不替换现有手工规则分类器。
- 本次不宣称合成数据已经证明线上准确率。
- 本次不引入 Transformer、ONNX Runtime 或新的运行时依赖。
