# 微信小程序房间同步修复实施计划

**目标：** 修复生产环境网络延迟下，房主遗漏成员加入事件、随后因旧 revision 操作冲突，且必须退出重进才能恢复的问题。

**原则：** 后端继续使用 revision 做并发保护；小程序在 WebSocket 首次鉴权后主动对账，在刷新重叠时合并请求，并在 revision 冲突后自动拉取最新房间快照。

## 任务 1：补齐实时连接首次对账

- 修改 `apps/miniprogram/tests/wx-realtime.test.ts`，先证明首次 `auth.ok` 当前不会触发状态对账。
- 修改 `apps/miniprogram/src/adapters/wx-realtime.ts`，让房间页首次鉴权触发房间快照对账；重连鉴权继续触发房间与轮次双对账，避免游戏页首次连接产生刷新重连循环。

## 任务 2：保证房间刷新不会丢失

- 增加房间页同步测试，覆盖刷新进行中再次收到刷新信号、操作进行中收到刷新信号、旧房间响应晚到。
- 修改 `apps/miniprogram/src/pages/room/index.ts`：串行合并刷新请求；按房间 ID 和 revision 单调应用快照；实时连接持有的 revision 随快照更新。

## 任务 3：revision 冲突自动恢复

- 增加房间页测试，覆盖 `ROOM_REVISION_CONFLICT` 后自动刷新并显示最新成员和 revision。
- 修改房间错误处理，不再要求用户退出重进；保留后端并发保护和可见提示。
- 重置离开页面后的模块级房间状态，避免新页面继承旧会话。
