# 周围菜品小程序端实施计划

## 目标

在小程序中完整实现已经确认的“周围菜品”流程：用户自备高德配置，客户端定位并直接搜索高德周边餐厅，按评分取结果，按内置大类聚合后复用现有游戏和结果页。

## 约束

- 高德 Key 与 `securityJsCode` 只保存在小程序本地，不进入后端和仓库。
- 保留现有大类、小类、自定义、多人游戏流程。
- 采用测试驱动：每个逻辑模块先增加会失败的测试，再实现最小代码，再运行相关测试。

## 任务 1：抽取可跨端复用的分类规则

1. 增加 `client-core` 的周边商家分类模块测试，覆盖：品牌规则、店名括号只去掉门店后缀、高德分类参与判断、重庆/蜀/广东/茶餐厅等高置信规则，以及中性名称归入“其他”。先运行测试确认失败。
2. 将 Web 当前纯 TypeScript 分类规则迁移到 `client-core` 并从入口导出；Web 原路径改为兼容性 re-export，保持现有 Web 测试和 fastText 调用不变。
3. 增加小程序端按内置大类聚合的纯函数测试，覆盖忽略“其他”、缺失模板、去重门店和内置封面来源；先失败后实现。

## 任务 2：小程序高德 REST、配置和本地搜索会话

1. 增加配置存取测试，验证 Key/securityJsCode 的本地读写、非法值忽略和清理。
2. 增加高德 REST 响应解析和请求测试，覆盖 `status=1`、评分解析、图片解析、分页、去重、评分排序、最多 200 候选和高德错误码。
3. 实现 `wx.request` 高德适配器。请求参数包含用户配置、GCJ-02 坐标、搜索半径、`types=050000`、`extensions=all`、每页 50 条和页码；不经过自有后端。
4. 增加最近位置、搜索会话和周围菜品轮次的本地存储适配器，限制数据量并在读取时校验结构。

## 任务 3：设置页和数据集入口

1. 先更新小程序页面源文件测试，要求设置页出现高德 Key/securityJsCode 输入与保存入口，数据集页显示可用的周围菜品入口。
2. 在设置页加入高德配置编辑，不影响自定义菜品编辑、脏数据确认和构建信息；从 `?return=nearby` 进入时保存后回到周围菜品页。
3. 数据集页根据本地配置进入周围菜品页，未配置时进入设置页；取消灰色“待上线”状态。
4. 注册 `pages/nearby/index` 并更新页面测试。

## 任务 4：周围菜品搜索页

1. 为页面状态、半径和数量选择增加测试：自动定位、手动选点、重新定位、重新搜索、10/20/30 结果数、加载/失败/空结果/结果不足状态和开始游戏按钮。
2. 实现页面：读取本地配置与搜索缓存，调用 `wx.getLocation`，定位失败时回退上次位置或允许 `wx.chooseLocation`，直接调用高德 REST 适配器。
3. 展示按评分排序的门店列表和高德分类；开始游戏前加载内置目录、只取大类模板、执行分类规则并聚合；无可用大类时不允许开始。
4. 使用内置目录封面并把聚合后的周围菜品轮次写入本地，进入现有单人游戏页 `dataset=nearby`。

## 任务 5：接入现有游戏和结果页

1. 先增加游戏恢复测试，覆盖周围菜品轮次从本地恢复、保留搜索生成的顺序、喜欢/不喜欢/撤销持久化和完成跳转。
2. 游戏页增加 `nearby` 数据集分支，直接读取已聚合的本地轮次；不改变现有卡片结构和手势。周围菜品卡片把“代表美食”显示为“附近门店”，使用聚合门店名称并沿用截断样式。
3. 结果页增加周围菜品轮次分支，展示喜欢的大类封面和门店名；返回数据集时清理本地轮次，重新开始时回到周围菜品搜索页。
4. 验证小程序多人、自定义、普通大类/小类路径仍引用原存储和原接口。

## 任务 6：验证和交付

1. 运行 client-core、Web 和小程序相关测试，再运行小程序 TypeScript 检查和构建。
2. 检查构建产物中没有开发者高德 Key，确认直接高德请求使用的是运行时用户配置。
3. 运行 `graphify update .` 更新知识图谱。
4. 查看 git diff，确认只包含本功能及规格/计划文档，不提交用户未要求的 commit。
